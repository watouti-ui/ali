What it does

One sentence, then the mechanism.

The agent polls 62 job sources every morning, collapses the same opening found in several places into one record, discards roles the candidate cannot actually take, scores everything that survives against a verified evidence bank, and reports only what crossed the threshold since yesterday.

Coverage

Two source types doing different jobs.

Aggregators (LinkedIn, Indeed) do broad discovery — they find employers nobody thought to name. ATS boards do the opposite: complete, authoritative coverage of one named employer with no ranking algorithm in between. Both are needed. One Mastercard role appeared on LinkedIn and on their Workday board, but only the board can guarantee nothing at that employer was missed.

Three decisions worth knowing

Code decides what code can decide

Scoring a job description against fifteen years of career evidence is judgement, and no weighted keyword count does it honestly. But the weighted total, the tier bands and the surfacing rule are arithmetic. Splitting them means the thresholds are recalibrated by editing a config file rather than re-prompting a model, and two runs on the same input produce the same shortlist.

Blockers suppress; flags do not

The candidate holds no PMP and was never awarded a bachelor's degree, so a posting mentioning either matters. But "PMP preferred" and "PMP required" are one word apart, and degree lines are frequently boilerplate an employer waives for fifteen years of evidence. Regex cannot tell those apart. So code raises a flag and the reasoning stage decides with the description in front of it. The asymmetry is deliberate: a false blocker is an opportunity that is never seen and never known about.

Evidence carries its own constraints

A high score licenses building a real application, so anything the score cites has to survive the interview it leads to. Constraints travel with the evidence in config — one flagship programme was approved for rollout but has not run, so its measures are targets and may never be presented as achieved outcomes.

How quality was established

Every significant bug was found by running against real data, not by writing more tests first.

  • Three deduplication failures. The same opening reached the system with a different requisition ID per source, a different location granularity per source, and a Workday office name in parentheses. Each was fixed narrowly after measuring: of eighteen same-employer-and-title groups, only one was a true duplicate — a blunt fix would have merged genuinely separate roles in Dublin and Cork.
  • Two false suppressions. Senior "Associate Director" roles were being discarded on the word associate, and an "Assistant Vice President" — mid-senior in banking — as too senior. Blocked count fell from six to one, and the survivor was a genuine mismatch.
  • Two title traps caught by reading descriptions. One role titled "Director, Platforms Operating Model" is a fund-accounting product owner in the body. Another with an ideal programme-management title requires a ten-year software development background the candidate does not have. Both score below threshold. Title similarity is not qualification.

77 unit tests, including a regression for every bug above.

Not built yet

Stated plainly, because a summary that implies more than exists is worse than no summary.

  • ×Application generation. Tailored CV and cover letter from the requirement-to-evidence map.
  • ×Inbox tracking. Recruiter replies, interview invitations and rejections are not yet detected.
  • ×Interview intelligence and post-interview review.

Risks and dependencies

Scoring is uncalibrated

The ranking is defensible but unvalidated. A review page exists for marking roles as pursue / not-for-me, and the daily digest is designed to gather the same signal continuously rather than as a single sitting. Until then, treat the ordering as a strong starting point rather than a verdict.

One credential is a single point of failure

The aggregator searches need an Apify API token in the environment. Without it the run degrades to ATS boards only — roughly a quarter of current volume. The pipeline isolates per-board failures so this cannot break a run, and the runbook requires the degradation to be reported rather than presented as a full result.

Enterprise search is imprecise

Workday's full-text search matches sales and finance postings that merely contain the search words, so a third of that source's volume is discarded before scoring. It is working as designed — boards enumerate, filters discriminate — but the yield per fetch is lower than the aggregators'.
